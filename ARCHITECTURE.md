# Architecture

The MVP is a zero-install local browser application. `index.html` loads only adjacent CSS and classic JavaScript files, so it runs from `file://` without a server or build. There are no remotely loaded libraries, CDN resources, browser outbound API calls, telemetry, analytics, cloud storage or runtime AI. The content security policy blocks network connections and limits resources to local files and local photo blobs.

`model.js` owns vocabulary, relationships, validation and pure mutations. `assurance.js` owns the deterministic deployment rules engine and its data validation. `meraki.js` parses local snapshots and stages review candidates. `transformation.js` parses workbook projections, reconciles source records and validates architect enrichment; `transformation-views.js` renders portfolio screens. `demo.js` creates synthetic data. `storage.js` owns IndexedDB and JSON backup/restore; the `workspaces` store holds the architecture model and the `photos` store holds selected image Blobs. `views.js` renders architecture and assurance screens; `topology.js` renders the local SVG graph; `app.js` coordinates actions and persistence. Dynamic text is escaped or assigned with `textContent`.

Phase 2 extends the same model and view modules with Branch Detail, Branch Estate Matrix and Branch Pattern Catalogue. A branch can be created with only a site name, optional code and proposed pattern; its LLD rows start Unknown. Devices, interfaces, circuits and subnets can then be added independently. Branch attributes record an entered value, classification and source. Patterns hold reusable target expectations; a branch inherits them through `patternId`. Delta rows compare only entered non-Target current values with the pattern and retain Unknown when either side is missing. The estate matrix summarizes explicit classifications and marks partial coverage. It is not an acceptance engine.

Branch evidence metadata lives in the workspace and identifies the associated branch object, type, source, date, classification, confidence and notes. Photograph Blobs remain in the `photos` store, linked by `photoId`. Adding or removing a photograph and its evidence record uses one IndexedDB transaction. Legacy workspaces and backups migrate without promoting evidence. JSON backup includes the complete workspace and photo data.

Phase 3 adds schema 3 assurance collections. An active baseline snapshots Design Intent; sourced Observed and As-Built records are append-only and separate. A local run compares the active baseline with the latest Observed record for each rule and stores immutable result snapshots with observation source. As-Built records are displayed independently and never substituted for Observed data. Acceptance gates evaluate the run deterministically: any Critical mandatory Fail is FAILED, while unresolved mandatory failures or Unknown results prevent acceptance. Approved noncritical exceptions can permit conditional acceptance, which still requires an explicit architect record. Imported result snapshots and acceptance records are checked against the deterministic rules and gates. Migration adds rules and gates but no synthetic observations or baselines to an existing workspace. No AI or vendor connection participates in evaluation.

Phase 4 adds an optional macOS Keychain-backed collector. It makes fixed-host read-only Dashboard GET requests and projects raw responses into an allowlisted JSON snapshot outside Git. The browser selects that file, maps its network to a branch and stages supported candidates with source metadata. Each candidate needs an explicit Apply or Dismiss action; Apply appends an Observed assurance record. It does not confirm facts, alter Design Intent or trigger validation. The core browser app still makes no outbound request and runs without the collector.

The Transformation Portfolio loads a locally bundled XLSX parser, maps the two expected sheets, and keeps source display values with row traceability. Import preview compares source identities and reports new, changed, removed, date, dependency and status changes before a confirmed import writes to IndexedDB. The original workbook is not stored. Architecture mappings and gates live in separate collections and survive source re-import. Timeline markers remain separate from Start/End dates; quality checks flag conflicts without correction. Mappings reference existing architecture IDs and can highlight affected topology nodes. JSON backup includes the projection and enrichment.

Current, Transition and Future are time states. Design Intent, Observed, Validated and As-Built are perspectives. Evidence classifications are separate and cannot be inferred from a readiness status. Facts, sources, evidence, validation rules and results retain provenance. The same snapshot boundary can serve future read-only vendor adapters; Observed records and architect confirmation still require explicit review. The optional collector is the only vendor connection; the browser remains offline.

Browser storage is scoped to the browser profile and file origin. Native macOS packaging and Catalyst SD-WAN Manager integration are deferred. The browser file picker is used for JSON backups, XLSX plans and photographs; the application does not scan local directories.
