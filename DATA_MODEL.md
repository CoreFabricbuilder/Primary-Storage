# Data model

The active workspace (`schemaVersion: 8`, `id: active`) contains a Programme and collections with stable IDs. Core entities are Domain, Site, Branch, Device, Interface, Circuit, VLAN, VRF, SD-WAN VPN, Subnet, Routing Adjacency, Service and Branch Pattern. `components` and `topologyLinks` provide the logical graph; `componentStates` map a component to Current, Transition or Future and its perspective, classification and source.

`branches` hold site code, location, assigned pattern, explicit current confidence, deployment readiness, validation status and last update. These fields may remain Unknown or empty. `branchPatterns` hold a unique pattern code, intended use and nullable expectations for WAN Edge quantity/transports, LAN devices/handoff, Wi-Fi APs/SSIDs, VLANs, VRFs, SD-WAN VPNs, routing, resilience, management, power and optics. `branchAttributes` hold current Physical or Logical values with classification, source, note and timestamp. Missing rows mean Unknown. Target expectations are inherited, not copied into the branch.

A new branch creates a Site and 33 Unknown LLD rows (11 categories across three time states). Its device list starts empty; Device, Interface, Circuit and Subnet records can be added independently as information becomes available.

`lldReadiness` is one row per site, state and category (Physical, IP Addressing, VLAN, VRF, SD-WAN VPN, Routing, Security, Management, Patching, Optics and Services). Its status and evidence classification are independent. `decisions` include code, title, domain, status, decision, rationale, superseded decision, affected components, source, date and classification. `dependencies` link upstream and downstream components, state, status, decision and classification.

`sources`, `facts`, `evidence`, `validationRules` and `validationResults` preserve provenance and validation. Classification values are Unknown, Observed, Client Confirmed, Architect Confirmed, Inferred, Target and As-Built. Perspective values are Design Intent, Observed, Validated and As-Built. An observed or inferred fact is never promoted automatically.

`branchEvidence` records type, source, date, classification, confidence, notes and one associated Branch, Cabinet, Device, Interface, Circuit, Wireless AP or Switch. Photograph evidence links a local IndexedDB Blob by photo ID; reference types store metadata only. The blob store retains image name, type and branch association. JSON export encodes blobs as data URLs; import checks the photo/evidence link and replaces workspace plus photos in one transaction. Migration retains legacy photograph evidence.

Deployment assurance uses separate collections: `assuranceRules` (category, domain, severity, mandatory flag, comparator, optional pattern key), `assuranceObservations` (branch, rule, Observed or As-Built perspective, value, source, timestamp), `assuranceBaselines` (branch, source, status, rule targets), `assuranceRuns`, `assuranceResults` (outcome, expected/observed snapshots, observation ID and source), `assuranceExceptions`, `acceptanceGates` and `acceptanceRecords`. Run outcomes are Pass, Warning, Fail, Unknown or Not Applicable. Severity is Critical, High, Medium, Low or Informational. Acceptance statuses are Ready, Ready with Exceptions, Not Ready, Accepted and Conditionally Accepted. A baseline target of `N/A` is an explicit Not Applicable; missing targets remain Unknown. Schema 1 and 2 workspaces and backups migrate through schema 3. Schema 3 workspaces migrate to schema 4 without vendor observations.

`merakiBatches` records branch, organization/network IDs and name, snapshot/import times and source. `merakiCandidates` records batch, branch, assurance rule, proposed value, provenance, Observed classification, Pending/Applied/Dismissed status and optional applied observation ID. An Applied candidate must link to a matching sourced Observed record. Raw snapshots and API credentials are not stored in IndexedDB. JSON backups retain review history.

Transformation collections: `transProgrammes`, `transProjects` (Project / TA), `transStreams`, `transActivities`, `transDependencies`, `transMilestones`, `transMappings`, `transGates`, `planImports`, `importChanges` and `dataQualityIssues`. Streams and activities have stable source keys, source projections with sheet/row/all displayed cell values, parsed dates and a `removed` marker. Streams retain month markers and dependency text; activities retain planning status, schedule, participants, line and notes. Import changes and quality warnings link to a Plan Import.

`transMappings` links a stream/activity to existing Domain taxonomy, Site, Branch, Component, Branch Pattern, Decision, Dependency or Source IDs, or to an HLD/LLD/validation reference. `transGates` stores architect-selected Planned, Architecture Defined, LLD Ready, Implementation Ready, Deployed, Validated or As-Built independently of source Planning Status. Detailed activity-to-stream links are architect-controlled. Schema 4 workspaces migrate to schema 5 with empty transformation collections; only the synthetic demo seeds portfolio data.

`sdwanBatches` records a mapped Branch or Campus scope, Manager label, Cisco Site ID, snapshot/import timestamps, query coverage and device count. `sdwanCandidates` records normalized metric, value, provenance and Pending/Applied/Dismissed review state. Apply appends a sourced `sdwanObservations` record classified Observed. `sdwanTargets` holds versioned, architect-sourced Design Intent values with one Active version per scope. `sdwanRuns` references a target version and stores overall state; `sdwanResults` snapshots target, observation, source, comparator outcome and severity. Uncovered or unapplied values remain Unknown. Schema 5 workspaces migrate to schema 6 with empty SD-WAN collections. Raw vendor responses and credentials are never stored in IndexedDB.

Phase 7 adds `serviceFlows` (named source/destination components, time state, classification and source) and `segmentationLinks` (VRF/VPN/VLAN/Subnet to a typed architecture object, classification and source). Logical path nodes and links are calculated from state-filtered topology, not stored as observed reachability. Site co-location derived for search is labelled context, not segment membership.

`deploymentBaselines` are append-only As-Built snapshots of sourced Observed values from an Accepted or Conditionally Accepted assurance run, plus a ready SD-WAN run if one was available before acceptance. Each record references the acceptance and runs, architect, rationale, timestamp and frozen metric values/provenance. `driftReviews` are append-only architect classifications for a later observation and baseline metric, with decision ID/status snapshot and rationale. No later observation is distinct from No Change. Schema 6 workspaces migrate to schema 7 with empty Phase 7 collections; existing vendor and assurance histories are retained.

Schema 8 adds `currentReportImports` (source filename/date, import time, row and change counts) and `currentBranchReports` (branch, import, Location UID, source row/date, Current/Observed classification and 26 source fields). Location UID, including leading zeros, is the primary match key; one unique exact name may link an existing branch whose site code is empty. Each changed report creates a new snapshot; repeat imports of the same dated values are idempotent. Reported connectivity, counts, address and subnet strings remain unvalidated source values. New branches receive an all-null `BP-UNASSIGNED` target pattern and Unknown LLD categories. Schema 7 migrates with empty report collections.

The overview derives counts and distribution buckets from the latest `currentBranchReports` snapshot per branch, with source warnings recalculated from retained fields. Missing or nonnumeric switch/AP counts are excluded from reported totals. A target-pattern coverage count requires at least one non-null expectation; the all-null import pattern remains Unknown. The Scenario Explorer adds no collection or migration. It derives a temporary comparison of `branchAttributes` against a selected `branchPatterns` target. Outcomes are Aligned, Change to review, Current unknown or Target unknown. Current classification and source remain attached to each row. Reported AP counts may be compared as Observed; connectivity/subnet strings remain context. Neither view changes assigned patterns, time-state records or baselines.

The report topology also adds no collection or migration. It projects temporary region, access-type and branch nodes from latest Current/Observed report snapshots. Association edges encode report grouping only; no circuit, dependency, WAN path or target state is inferred.

Schema 9 adds `libraryDocuments` (title, Local/External storage, source, note, Observed classification, timestamp, and either file metadata or an HTTPS URL) and `documentLinks` (document ID, typed object kind/ID, relationship note). Local bytes live in the separate IndexedDB `documents` store under the same stable ID. Links validate their target and are unique per document/object pair. Files and references do not automatically become facts, validation evidence or approved design. Schema 8 migrates with empty library collections.
