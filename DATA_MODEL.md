# Data model

The active workspace (`schemaVersion: 4`, `id: active`) contains a Programme and collections with stable IDs. Core entities are Domain, Site, Branch, Device, Interface, Circuit, VLAN, VRF, SD-WAN VPN, Subnet, Routing Adjacency, Service and Branch Pattern. `components` and `topologyLinks` provide the logical graph; `componentStates` map a component to Current, Transition or Future and its perspective, classification and source.

`branches` hold site code, location, assigned pattern, explicit current confidence, deployment readiness, validation status and last update. These fields may remain Unknown or empty. `branchPatterns` hold a unique pattern code, intended use and nullable expectations for WAN Edge quantity/transports, LAN devices/handoff, Wi-Fi APs/SSIDs, VLANs, VRFs, SD-WAN VPNs, routing, resilience, management, power and optics. `branchAttributes` hold current Physical or Logical values with classification, source, note and timestamp. Missing rows mean Unknown. Target expectations are inherited, not copied into the branch.

A new branch creates a Site and 33 Unknown LLD rows (11 categories across three time states). Its device list starts empty; Device, Interface, Circuit and Subnet records can be added independently as information becomes available.

`lldReadiness` is one row per site, state and category (Physical, IP Addressing, VLAN, VRF, SD-WAN VPN, Routing, Security, Management, Patching, Optics and Services). Its status and evidence classification are independent. `decisions` include code, title, domain, status, decision, rationale, superseded decision, affected components, source, date and classification. `dependencies` link upstream and downstream components, state, status, decision and classification.

`sources`, `facts`, `evidence`, `validationRules` and `validationResults` preserve provenance and validation. Classification values are Unknown, Observed, Client Confirmed, Architect Confirmed, Inferred, Target and As-Built. Perspective values are Design Intent, Observed, Validated and As-Built. An observed or inferred fact is never promoted automatically.

`branchEvidence` records type, source, date, classification, confidence, notes and one associated Branch, Cabinet, Device, Interface, Circuit, Wireless AP or Switch. Photograph evidence links a local IndexedDB Blob by photo ID; reference types store metadata only. The blob store retains image name, type and branch association. JSON export encodes blobs as data URLs; import checks the photo/evidence link and replaces workspace plus photos in one transaction. Migration retains legacy photograph evidence.

Deployment assurance uses separate collections: `assuranceRules` (category, domain, severity, mandatory flag, comparator, optional pattern key), `assuranceObservations` (branch, rule, Observed or As-Built perspective, value, source, timestamp), `assuranceBaselines` (branch, source, status, rule targets), `assuranceRuns`, `assuranceResults` (outcome, expected/observed snapshots, observation ID and source), `assuranceExceptions`, `acceptanceGates` and `acceptanceRecords`. Run outcomes are Pass, Warning, Fail, Unknown or Not Applicable. Severity is Critical, High, Medium, Low or Informational. Acceptance statuses are Ready, Ready with Exceptions, Not Ready, Accepted and Conditionally Accepted. A baseline target of `N/A` is an explicit Not Applicable; missing targets remain Unknown. Schema 1 and 2 workspaces and backups migrate through schema 3. Schema 3 workspaces migrate to schema 4 without vendor observations.

`merakiBatches` records branch, organization/network IDs and name, snapshot/import times and source. `merakiCandidates` records batch, branch, assurance rule, proposed value, provenance, Observed classification, Pending/Applied/Dismissed status and optional applied observation ID. An Applied candidate must link to a matching sourced Observed record. Raw snapshots and API credentials are not stored in IndexedDB. JSON backups retain review history.
